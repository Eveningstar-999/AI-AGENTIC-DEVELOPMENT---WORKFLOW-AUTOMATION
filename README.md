# AI Agent Workflow Automation

## Project Overview


This project documents my hands-on work with AI-agent-driven software engineering through a project-based engagement with Handshake AI, working on the Dynamo task environment.

The work focused on giving an AI coding agent structured instructions and requirements, providing the necessary context and constraints, and guiding the agent through software engineering tasks inside a structured GitHub repository. The workflow involved task definition, repository organization, implementation, testing, validation, debugging, and evaluation.

Rather than simply writing code manually, the project focused on understanding how an AI agent can be guided to independently execute structured software engineering work while still being evaluated against defined requirements and expected outputs.

## Role and Responsibilities


I worked as an AI Agent Specialist on a project-based task involving AI-assisted software engineering workflows.

My responsibilities included:

- Understanding structured software engineering requirements.
- Translating requirements into clear instructions for an AI coding agent.
- Providing the agent with relevant task context, objectives, constraints, and expected behavior.
- Working with structured GitHub repositories containing task specifications, source files, scripts, configuration, tests, and supporting files.
- Organizing task-specific resources and implementation components.
- Configuring task metadata and execution requirements.
- Guiding the AI agent through implementation and solution development.
- Running and reviewing generated solutions.
- Testing implementations against expected behavior.
- Investigating failures and debugging implementation issues.
- Refining instructions and requirements when necessary.
- Reviewing agent-generated outputs and iterating based on validation results.
- Working with Git and GitHub repository workflows.
- Working with Docker-based execution environments and reproducible setups.
- Working with proposal generation and proposal/pipelining workflows.
- Evaluating the completed task using automated validation and evaluation systems.

## Task Structure


The project used a structured task-based repository rather than a simple source-code folder.

The repository workflow included task-specific configuration, instructions, implementation files, testing components, and supporting infrastructure.

A `task.toml` configuration file was used for task metadata, requirements, and execution configuration. Task-specific resources were organized into dedicated directories so that the AI agent could access the information required for the task.

The workflow separated the task requirements, solution implementation, testing, and supporting resources into appropriate components. This helped maintain a clear repository structure and made the execution process more reproducible.

## AI Agent Workflow


The central part of the project was the interaction between structured requirements and an AI coding agent.

The workflow began with understanding the task requirements and defining what the agent needed to accomplish. I then provided detailed instructions, requirements, constraints, and contextual information to guide the agent.

The agent was expected to reason about the task, work with the repository, implement the required solution, and produce the expected outputs.

I reviewed the generated implementation rather than treating the first generated result as final. When issues appeared, I investigated the implementation, reviewed the outputs, refined the instructions or approach, and ran the workflow again.

This created an iterative development cycle:

1. Understand the task.
2. Define requirements and constraints.
3. Provide instructions to the AI agent.
4. Allow the agent to inspect and implement the task.
5. Run the solution.
6. Test the implementation.
7. Validate the outputs.
8. Identify issues or failures.
9. Refine the instructions or implementation.
10. Re-run the workflow.
11. Evaluate the final result.

## Automated Testing and Validation


Testing and validation were an important part of the project.

The workflow included automated testing and output validation using project test components such as:

- `tests/test.sh`
- `test_outputs.py`

These components were used to verify whether the implementation produced the expected behavior and outputs.

I worked with artifact-based validation to examine generated results and determine whether the completed implementation satisfied the task requirements.

When validation identified an issue, I reviewed the implementation, investigated the cause, refined the solution or agent instructions, and repeated the evaluation process.

This provided practical experience with automated testing, debugging, validation, and iterative software development.
